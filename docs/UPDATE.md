Refine the Encounter tab so that it functions clearly as the whole-incident overview for the report.

The Encounter tab should not duplicate the Stages tab. Its purpose is to capture incident-level indicators: what happened overall, whether key harms or control behaviours appeared anywhere in the incident, whether the report has enough detail for staged coding, and what early escalation cues are present.

The Stages tab will handle when behaviours occurred and how the encounter unfolded over time. The Encounter tab should remain a fast whole-case coding screen.

Add a brief note near the top of the Encounter tab:

“This tab captures whole-incident indicators. Use the Stages tab to code when and how behaviours occurred across the encounter.”

Yes

No

Avoid using both “unclear” and “unknown” as separate options unless the UI defines the difference.

If both are retained:

Unclear = the report mentions something but the meaning is ambiguous.

Unknown / not stated = the report does not provide the information.

10. Keep the tab efficient
Do not overload this tab.

The Encounter tab should be fast to complete and should capture the overall incident profile.

Detailed stage-by-stage coding belongs in the Stages tab.

Detailed movement coding belongs in the Mobility tab.

Detailed spatial mapping belongs in the GIS tab.

The Encounter tab should answer:

What happened overall?

What type of incident was this?

How severe was it?

Are there enough details for staged coding?

Is the sequence clear?

What key harm, control, or violence indicators appeared anywhere in the incident?

What early escalation cues were present?

11. Do not duplicate other tabs
Do not duplicate the Stages, Mobility, GIS, or Narrative tabs inside the Encounter tab.

The Encounter tab should remain a whole-incident overview. It should capture whether key indicators appeared anywhere in the incident, but it should not require the user to code when each behaviour occurred. Timing and sequence belong in the Stages tab.

Do not add detailed movement pathway fields here. Those belong in Mobility.

Do not add map or coordinate fields here. Those belong in GIS.

Do not add full narrative coding here. That belongs in Narrative.

Only add fields that help summarize the incident as a whole and determine whether it is suitable for staged analysis.
